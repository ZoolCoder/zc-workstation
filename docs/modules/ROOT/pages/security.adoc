= Threat model
:description: What zc-workstation protects against, and what it does not.

== What it protects

* *Nothing is applied that was not shown.* A saved plan refuses to apply when
  the machine changed since. The dashboard plans again before applying. The
  dotfiles provider applies only the planned paths.
* *Deletions need a person.* The CLI asks, the dashboard sends you to the
  terminal, and the MCP server cancels.
* *Nothing is uninstalled.* The packages provider only installs.
* *Untrusted mise configs stay untrusted.* Trusting one is a `MANUAL` step,
  never automatic.
* *Writes stay inside a target.* `localdir` writes through `os.Root`: a
  symlink or `..` cannot lead a write out of the directory.
* *The protocol stream stays clean.* Under `mcp`, installers get empty input
  and their output is captured, never written to the protocol stream.
* *The dashboard stays local.* Loopback only, `Host` checked against DNS
  rebinding, cross-site writes refused, strict CSP.

== What it does not

* *A config or manifest you did not write.* A Brewfile can name any package,
  a chezmoi source can run scripts, and a mise config can install any tool.
  Review them as you would a script.
* *The package sources.* Homebrew, apt, dnf, winget and mise verify what they
  download; `zc-workstation` adds nothing to that.
* *`sudo`.* apt and dnf installs run `sudo`, which asks for your password in
  the terminal. Agents cannot answer it.
* *An attacker who already has your shell.*

Report a problem through the repository's security policy, never a public
issue.
